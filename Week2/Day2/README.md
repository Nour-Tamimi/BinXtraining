##  Coin Flips & the Law of Large Numbers

**Goal:** simulate flipping a coin many times and confirm the proportion of heads approaches the true probability.

```python
import numpy as np

np.random.seed(42)
flips = np.random.randint(0, 2, size=10000)  # 0 = tails, 1 = heads
proportion_heads = flips.mean()
```

**Key insight:** `.mean()` on an array of 0s/1s (or `True`/`False`) automatically computes `sum / count`, which is exactly the definition of probability (favorable outcomes ÷ total outcomes). Since heads = 1, summing the array counts the heads, and dividing by the array length gives the proportion.

> **Generalization:** any event encoded as a boolean array → `.mean()` of that array = the probability of that event.

**Law of Large Numbers:** the more trials you run, the closer the simulated proportion gets to the true probability (0.5 for a fair coin). With few trials, expect noticeable noise (e.g. 0.4987 instead of exactly 0.5).

## `np.random.randint` vs `np.random.choice`

| Function | Use when |
|---|---|
| `np.random.randint(low, high, size)` | Equal probability across a range of integers (fair die, fair coin). `high` is **exclusive**. |
| `np.random.choice(a, size, p=[...])` | Custom/unequal probabilities, or picking from non-integer categories. |

**Biased coin example (70% heads):**
```python
flips = np.random.choice([0, 1], size=10000, p=[0.3, 0.7])
```
`p` must be the same length as `a`, line up positionally, and sum to 1.

## Normal Distribution

```python
np.random.normal(loc=0.0, scale=1.0, size=None)
```

- `loc` = **μ (mean)** — center of the bell curve
- `scale` = **σ (standard deviation)** — spread of the bell curve
- `size` = number/shape of samples

```python
samples = np.random.normal(loc=50, scale=5, size=10000)
plt.hist(samples, bins=50, density=True)
```


Note: this describes fixed percentage bands, **not** the min/max of your data — with enough samples, rare values further out (±3.5σ, ±4σ) will still occasionally appear.

### Important distinction: `np.random.normal` is direct sampling, not built from coin flips
`np.random.normal` uses its own dedicated algorithm (e.g. Box-Muller) to sample the bell curve directly — it does not internally simulate and sum coin flips.

The coin-flip connection is conceptual, not implementational: it's an illustration of the **Central Limit Theorem (CLT)** — summing/averaging many independent random events (like many coin flips) tends toward a normal shape, which explains *why* the normal distribution is so common in nature, not *how* `np.random.normal` is computed.

## Conditional Probability — Formula + Simulation

```python
P(A|B) = P(A ∩ B) / P(B)
```

**Pattern in code:**
```python
event_A = (...)   # boolean array
event_B = (...)   # boolean array
p_A_given_B = np.mean(event_A & event_B) / np.mean(event_B)
```


##  Reproducibility: `np.random.seed()`

NumPy's "random" numbers are actually **pseudo-random** — generated by a deterministic formula starting from a state called the seed.

```python
np.random.seed(0)   # any number works; it's just a fixed starting point
```

- Same seed → identical sequence of "random" values every run (reproducible).
- No seed → different values every run (based on system entropy).
- The specific number chosen (0, 42, etc.) is arbitrary — only consistency matters.

**Why it matters:** reproducible debugging, fair comparisons between experiments (e.g. comparing two models where only the thing being tested should differ), and being able to verify someone else's exact results.

##  Core Mental Checklist for Any New Probability Question

1. **What's the random process?** → map the scenario to a numpy function (`randint`/`choice` for discrete/equal or custom probabilities, `normal` for bell-shaped continuous data, `binomial`/`uniform` for their respective scenarios).
2. **What are the events?** → express each as a boolean condition on an array.
3. **What's being asked?** → plain probability (`.mean()`), conditional probability (`(A & B).mean() / B.mean()`), or a distribution shape (`plt.hist`).
4. **Compare to theory** → compute the hand/formula answer alongside the simulated one, using enough trials (100k–1M) for a close match.
